# Roadmap

This roadmap outlines the planned features and development priorities for Super Tux War.

## Current Status

### ✅ Completed (Phase 0 - Core Foundation)

- **Player Movement**
  - SMW-style physics (walk, run, jump)
  - Variable jump height
  - Coyote time and jump buffering
  - Ice block physics (reduced friction)

- **Level System**
  - 32×32 tile-based levels
  - TileMapLayer support (solid, semisolid, decoration)
  - Level thumbnails with auto-generation
  - Level info and metadata

- **Combat System**
  - Head stomp mechanics
  - Character death and respawn (2s delay)
  - Gravestone spawning
  - Score tracking

- **AI System**
  - NPC controller with pathfinding
  - Navigation graph generation
  - Jump arc physics simulation
  - Multiple CPU character support (up to 7 tested)

- **Character System**
  - Modular character components (physics, visuals, lifecycle)
  - Character selection (Tux, Beasty, Gopher)
  - Animation system
  - CPU color tinting

- **UI System**
  - Start menu with character selection
  - Level selection
  - Pause menu
  - Game over scoreboard
  - Dev menu (F11/F12 debug tools)

- **Editor Tools**
  - Level thumbnail baker plugin
  - Auto-baking on level save

## Phase 2: Audio System

### 🎵 Sound & Music

**Priority**: High  
**Status**: ✅ Complete (except item/power-up sounds — blocked on Phase 1 items)

All assets are original NES-style chiptune generated by the in-repo pipeline
(`tools/audio_gen/`, see its README) — MIT-licensed, reproducible with
`python tools/audio_gen/generate.py --all`.

**Sound Effects**:
- [x] Jump sound (`jump.ogg` + `jump_turbo.ogg` variant)
- [x] Stomp hit sound
- [x] Death sound
- [x] Respawn sound
- [ ] Item pickup sound (no items exist yet — Phase 1)
- [ ] Power-up activation sound (no power-ups exist yet — Phase 1)
- [x] UI interaction sounds (plus extras: skid loop, land, score, pause,
      match start; pre-made but unwired: `ui_move`, `ui_back`, `ui_tick`,
      `gravestone`, `drop_through`)

**Music**:
- [x] Menu music (`menu.ogg` — title theme)
- [x] Level music (`level01`–`level03`, one theme per level, seamless loops)
- [x] Victory/game over music (`victory.ogg` / `defeat.ogg` stingers)

**Technical Requirements**:
- [x] AudioStreamPlayer management (`AudioManager` autoload, EventBus-driven)
- [x] Sound effect system with pooling (12 voices, per-event cooldowns/caps)
- [x] Music system with crossfading (A/B players, pause-immune tweens)
- [x] Volume controls and settings (options popup in start/pause menu,
      persisted to `user://settings.cfg`, M = mute hotkey)
- [x] Audio bus configuration (Master/Music/SFX in `default_bus_layout.tres`)

## Phase 4: Game Modes

### 🏆 Game Modes

**Priority**: Medium  
**Status**: ✅ Six single-player modes shipped (team/network modes still require multiplayer)

Mode selection lives in the start menu (mode stepper + per-mode goal stepper).
Every mode is fully playable by the CPU AI (objective navigation, priority
targets, flee behavior). Architecture: `GameMode` base class + `ModeRegistry`
(`scripts/modes/`), mode instance spawned under the level scene per match;
scores broadcast via `EventBus.mode_score_changed`; mode HUD (timer/status/
toasts) injected by UIManager. Dev shortcut: `dev_launch.cfg` `[match]`
`mode="koth"` + `goal=30`.

**Shipped Modes**:
- [x] **Frag Limit**: first to N kills (the original mode)
- [x] **Time Limit**: most kills when the clock runs out (draws possible)
- [x] **Classic**: N lives, elimination, last-one-standing
- [x] **Coin Collection**: first to N coins (coins relocate if uncollected)
- [x] **King of the Hill**: sole occupant of the moving zone accrues points
- [x] **Chicken**: first killer becomes the slowed, tinted chicken — it earns
      points per second and +5 per kill; killing it transfers the role

**Still Planned** (need multiplayer/teams or new systems):
- **Team Deathmatch**: Teams compete for most stomps
- **Capture the Flag**: Grab the flag and return to base
- **Race Mode**: First to lap through numbered gates
- Meta-modes (Tournament / Tour / World map)
